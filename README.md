# wstunnel на Render

Этот проект разворачивает только **wstunnel-сервер** как Render Web Service. Render принимает внешний HTTPS/WSS-трафик и передаёт WebSocket в контейнер. Сервер wstunnel не является WireGuard-сервером и не создаёт полноценный VPN-интерфейс сам по себе: клиентское устройство получает локальный SOCKS5-прокси, через который можно направлять трафик.

## Что получится

Схема выглядит так:

```text
Телефон: wstunnel client
    локальный SOCKS5 127.0.0.1:10808
                │
                │ WSS через HTTPS
                ▼
Render Web Service: wstunnel server
                │
                ▼
        сайты и TCP-сервисы в интернете
```

Для просмотра сайтов в одном приложении можно указать SOCKS5-прокси `127.0.0.1:10808`. Для маршрутизации всего Android-трафика потребуется VPN/SOCKS-оболочка, например V2rayNG или совместимый клиент; это отдельный компонент, не встроенный в wstunnel.

## Деплой в Render

Создай новый Web Service из этого репозитория. Render должен использовать Dockerfile из корня проекта. В настройках сервиса установи переменную окружения:

```text
WSTUNNEL_PATH=<длинная случайная строка>
```

Пример безопасного значения:

```text
WSTUNNEL_PATH=7f3c9a2e1d5b4c8a6e0f9b2d4a7c1e8
```

Не публикуй это значение в GitHub, README, скриншотах или сообщениях. Оно выполняет роль общего секрета: сервер принимает только WebSocket upgrade-запросы с этим path prefix.

В `render.yaml` выбран бесплатный инстанс, чтобы начать без платного включения. Он подходит для теста, но Render может остановить его после 15 минут без входящего трафика, перезапустить сервис и ограничивает бесплатные часы в месяц. Для постоянно доступного туннеля в настройках Render можно выбрать любой платный тип сервиса; схема Docker и клиентская команда при этом не меняются.

После успешного деплоя Render выдаст адрес вида:

```text
https://wstunnel-proxy-xxxx.onrender.com
```

В клиенте используй тот же адрес с протоколом `wss://`:

```text
wss://wstunnel-proxy-xxxx.onrender.com
```

Внешний TLS завершается на Render, поэтому контейнер слушает внутренний `ws://0.0.0.0:${PORT}`. Не меняй `${PORT}` на фиксированный порт: Render передаёт его сервису автоматически.

## Android: запуск клиента

На Android нужен отдельный процесс wstunnel. Практичный вариант — **Termux из F-Droid**, а не случайная копия из стороннего сайта. Скачай из раздела Releases проекта wstunnel бинарник для архитектуры телефона, обычно `android_arm64`, и помести его в Termux, например в `~/bin/wstunnel`.

В Termux выполни:

```bash
mkdir -p ~/bin
chmod +x ~/bin/wstunnel
```

Запусти локальный SOCKS5-порт:

```bash
~/bin/wstunnel client \
  -L 'socks5://127.0.0.1:10808' \
  -P 'ТВОЙ_WSTUNNEL_PATH' \
  --tls-verify-certificate \
  wss://ТВОЙ-СЕРВИС.onrender.com
```

Замени `ТВОЙ_WSTUNNEL_PATH` и `ТВОЙ-СЕРВИС.onrender.com` на свои значения. Пока эта команда работает, SOCKS5-прокси доступен только на телефоне по адресу `127.0.0.1:10808`.

Не отключай Termux от памяти и исключи его из оптимизации батареи Android, иначе система может остановить процесс. При перезапуске телефона команду нужно запустить заново, если не настроить отдельную автоматизацию запуска.

## Как пользоваться прокси

Для одного приложения, которое поддерживает SOCKS5, укажи:

| Параметр | Значение |
|---|---|
| Тип | SOCKS5 |
| Адрес | `127.0.0.1` |
| Порт | `10808` |
| DNS через прокси | включить, если приложение предоставляет такую настройку |

Например, в браузере с поддержкой SOCKS5 укажи эти параметры. Важно включить удалённое разрешение DNS, иначе DNS-запросы могут идти напрямую через мобильного оператора.

Для всего Android-трафика нужен отдельный клиент, который умеет работать в VPN/TUN-режиме и отправлять трафик в локальный SOCKS5. В нём добавь исходящий SOCKS5-сервер `127.0.0.1:10808`, включи VPN/TUN-режим и проверь, что DNS также направляется через прокси. Названия полей различаются по приложениям, поэтому универсальный QR-код или стандартный WireGuard-профиль здесь невозможны.

## Проверка работы

После запуска клиента проверь, что локальный порт слушается:

```bash
pkg install net-tools
netstat -an | grep 10808
```

Затем проверь прокси из Termux:

```bash
pkg install curl
curl --socks5-hostname 127.0.0.1:10808 https://ifconfig.me
```

Если команда возвращает внешний IP, соединение через SOCKS5 работает. Если Render отвечает ошибкой 404/400 или клиент не подключается, сначала проверь точное совпадение `WSTUNNEL_PATH`, адрес `wss://` и наличие активного Render-сервиса.

## Ограничения

Этот вариант не использует WireGuard и не предоставляет стандартный VPN-профиль `.conf`. Он передаёт динамические TCP-соединения через SOCKS5; UDP-трафик и приложения, которым нужен полноценный системный VPN-интерфейс, зависят от возможностей дополнительной VPN/SOCKS-оболочки на телефоне.

Render Web Service может перезапускаться или менять инстанс, поэтому клиент должен автоматически переподключаться. Бесплатный инстанс также может уснуть после 15 минут без входящего трафика и имеет месячный лимит бесплатных часов; для постоянного использования нужен платный тип сервиса или готовность принять эти ограничения.

На iPhone этот сценарий существенно сложнее, поскольку нельзя просто запустить произвольный бинарник wstunnel в фоне. Для iOS потребуется приложение с нативной поддержкой нужного WebSocket-туннеля или промежуточный сервер/клиент, поэтому приведённые инструкции ориентированы на Android.
